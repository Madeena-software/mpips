# Pipeline conditions and bounded feedback loops

State: Validated/Published, 2026-11-02. Owner/authority: Arif explicitly approved replacing the DAG-only product direction with a pipeline builder, custom stopping conditions plus a hard iteration limit, True/False gates, and then instructed “okay implement it”.

Objective: implement executable pipeline control flow across the existing canvas, Laravel validation, node catalog, and scientific executor while retaining old acyclic pipeline behavior and service isolation.

Approved requirements and technical contract:
- FLOW-1: a Condition gate evaluates a restricted declarative expression and sends its image through exactly one of true_image/false_image. Inactive branches skip downstream processing; exclusive Branch Merge joins the selected branch without waiting for the inactive branch.
- FLOW-2: an explicit Loop node accepts input_image (initial), feedback_image (repeat), and stop_image (condition exits). current_image feeds the loop body; output_image is emitted only on termination. Return edges to feedback_image/stop_image are the only permitted cycles. Loop parameters include max_iterations (integer 1..100, default 10), result_mode latest/best, score_metric mean/std/entropy, and maximize/minimize selection. Iteration 1 starts from the seed; later iterations receive the previous feedback image. A true/false gate may drive stop/repeat. Cap exhaustion terminates with a distinct reason and returns the chosen result.
- FLOW-3: custom conditions are parsed with an allowlist, never eval, arbitrary code, attribute access or calls. Support numeric/bool literals, named variables iteration/value/previous_value/mean/std/entropy/delta_mean/delta_std/delta_entropy/delta_value, arithmetic + - * / %, comparisons, and/or/not and parentheses. Previous values exist only within the same gate and loop run; unavailable previous scalar inputs give a clear error. Expressions are bounded in size/complexity and fail clearly on invalid/nonfinite values. Image measurements are computed from the current image; no clinical meaning is claimed.
- FLOW-4: validate loop structure before storage, submission or execution. Reject unbounded/crossing/nested loops, IO inside loop bodies, missing seed/returns, body leakage and undeclared cycles. First release supports independent or sequential explicit loops, not nested loops. Estimate work and reject over 10000 stage evaluations. Keep cancellation callbacks, temporary-file cleanup, original-image references and per-output uploads intact. Return iteration/branch/stop-reason details in execution metadata.
- FLOW-5: expose Condition, Loop and Branch Merge in a Control Flow palette with named ports and ordinary Inspector fields. Retitle the visible builder as Pipeline Builder; retain existing route URLs/import formats. Permit and distinctly render valid feedback edges; arrangement ignores return edges. Old graphs remain compatible. Control-flow pipelines run on the scientific server; browser eligibility must reject them explicitly.

Scope: mpips/dag control-flow planning/scheduling, processor catalog/registry, executor integration, focused tests and protocol docs; mipc control-flow catalog/validation, canvas/Blade/styles, focused tests and product terminology.
